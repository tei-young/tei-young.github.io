CASE 01

AI·자동화로 TC 작성 4–5일 → 1–2일, 반복 검증은 배포마다 자동 실행

20–30%QA 리소스 절감

TC 작성과 반복 검증에 드는 시간을 줄이기 위해 AI 기반 도구와 자동화 테스트를 직접 구축했습니다.

  • AI 기반 TC 생성 — Figma MCP와 복수의 skill-subagent를 구성한 Claude Code 기반 도구 제작, 최종 사용 TC 기준 70~90% 자동 산출
  • API 자동화 — 전체 구매 플로우(로그인 → 결제 → 배송 완료 → 구매 확정)를 Jenkins job으로 백엔드 배포마다 상시 실행 (Postman → Python 이관 중)
  • 앱 E2E 자동화 — Maestro 기반 반복 검증 자동화(약 50% 구축), 배포 체크리스트 수행 2일 → 1일 이내
  • 자동화 신뢰성 검증 — AI가 만든 테스트가 실제 화면·기능을 근거로 판단하는지 확인하기 위해, 앱 코드에 의도적으로 버그를 주입해 기대대로 실패하는지 검증하는 방식을 직접 고안
백엔드 배포 트리거로 상시 실행 — 전체 회귀 없이 이상 구간 즉시 탐지
결과
  • TC 작성 기간 4–5일 → 1–2일로 단축
  • 결제 모듈·쿠폰 발급·마트 주소 변경 API 오류를 배포 전 조기 검출

CASE 03

배포를 미루는 결정과, 배포를 막는 결정을 직접 내리다

릴리즈 가부를 이슈의 성격과 영향범위를 근거로 판단하고, 이해관계자를 설득해 일정을 조정했습니다.

  • 배포 연기 — POS v2→v3에서 핵심 기능인 상품가격 동기화가 동작하지 않는 blocker급 이슈 발생. 수정 후 재확인 과정에서 이미 검증한 기본 동작에서도 문제가 나와 기존 테스트 결과를 신뢰할 수 없다고 판단, 사업부·PM·개발자에게 근거를 공유해 추가 테스트 일정 확보
  • 핫픽스 반려 — 영업·사업부의 B2B 편의기능 핫픽스 요청에 대해, 더 높은 우선순위 개발이 진행 중이고 정규 배포 프로세스로 안정성을 확보하는 편이 낫다고 판단해 근거를 들어 반대
  • 운영 원칙 — 사업 요청이라도 시급도가 낮고 영향범위가 크면 반대하며, 불가피한 경우 진행 중이던 배포를 미뤄 영향범위 검증을 확보한 뒤 배포
결과
  • 연기된 일정 내 검증을 완료해 정상 배포
  • 반려한 기능은 다음 정규 배포에 포함, 공백 기간은 영업이 수동 대응으로 커버
CASE 04

POS 연동 데이터 흐름을 직접 분석해 크리티컬 참조 오류를 QA 전 차단

마트 POS 기기의 상품 데이터를 자사 서비스로 연동하는 핵심 프로그램의 v2→v3 리빌드를 담당했습니다.

  • 히스토리 추적이 어려운 v2를 데이터 플로우 기준으로 직접 플로우차트화해 TC 작성 → 이 TC가 v3 기획의 초안 역할
  • POS 업체별로 DB 엔진(MySQL·Oracle 등)과 테이블 구성이 모두 달라 업체 특성별 분기 케이스 설계, 실데이터 복사·분석(AI 활용)으로 특이사항 명세화
  • QA 전 DB를 동일하게 재구성·간이 테스트해 특정 POS의 상품 테이블 참조 오류(개발 DB 조사 오류)를 규명
  • 사용량 증가가 예상되던 미검증 기능(전단 상품)을 TC 범위 밖까지 선제 검증해 잠재 결함 발견
POS DB → 연동 프로그램 v3 → 자사 서비스 · 전달 지점과 참조 테이블 검증
결과
  • 크리티컬급 이슈를 TC 작성 단계에서 사전 차단
  • 이슈의 50% 이상에서 로그 기반으로 원인·발생 지점을 함께 전달해 개발 핸드오프 속도 향상
CASE 05

외부 서비스 내재화를 기획 정의부터 릴리즈 판단까지 단독으로 끌고 가다

외부 알림톡 서비스를 자사 서비스로 내재화해, "고객에게 낮은 단가로 이벤트 알림을 보내고 싶다"는 기존 고객 니즈를 구현하는 프로젝트를 처음부터 끝까지 담당했습니다.

  • 기획 고도화 — 정의가 누락된 항목을 질문으로 구체화(임시저장은 내부 미리보기만 갱신 / 최종저장은 실제 유저 노출 화면에 반영)
  • 로직 검토 — 내재화 시 삭제하려던 자사 기능 연동을 유지하되 컴포넌트를 정확히 매핑해 누락을 최소화하는 방향으로 개선 기여
  • 배포·모니터링 — 진행 중 발생한 이슈의 회귀 테스트와 기본 기능 확인 후 릴리즈 가부 판단, 사업·PM과 협의해 강제 업데이트 여부까지 결정

결과문제 식별 → 기획 정의 → 수행 → 배포 → 모니터링까지 한 제품을 관통해 책임
